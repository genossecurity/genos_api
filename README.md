# Phase 2 — Notes

## 1. Training, Test and Validation Data

Phase 2 uses two separate data sources: a synthetic benign baseline and a real-world malicious corpus scraped from Atomic Red Team.

### Benign baseline — `synthetic_benign_baseline.csv`

Generated by `synthetic.py`.

| Setting | Value |
|---|---|
| Total samples | 50,000 |
| Schema | `command` (string), `label` (always 0) |
| Generation | Fully synthetic; all commands are normalised before writing |

**Command categories and sampling weights:**

| Category | Binaries | Weight |
|---|---|---|
| SYS_ADMIN | `ipconfig`, `netstat`, `tasklist`, `whoami`, `net.exe`, `sc.exe`, etc. | 3.0 |
| OFFICE_APPS | `winword`, `excel`, `outlook`, `powerpnt`, etc. | 1.0 |
| BROWSERS | `msedge`, `chrome`, `brave`, etc. | 1.0 |
| DEV_TOOLS | `git`, `npm`, `node`, `python`, `docker`, etc. | 1.0 |
| NET_TOOLS | `ping`, `nslookup`, `tracert`, `curl`, `ssh` | 1.0 |
| POWERSHELL | `powershell.exe`, `pwsh.exe` | 1.0 |
| OS_SERVICES | `svchost`, `lsass`, `runtimebroker`, etc. | 1.0 |

Hardening counter-weights are included so the model does not over-fit on simple benign patterns: service query flags, running process filters, network session stats, etc.

All commands are passed through `normalize_command()` before being written to the CSV — the same function used at inference time — so the training distribution exactly matches production input.

If baselines are collected from multiple machines they can be merged and deduplicated with `csv_merge.py` before training.

### Malicious corpus — `mitre_atlas_raw.csv`

Generated by `mitre_atlas_scraper.py`.

| Setting | Value |
|---|---|
| Source | [Atomic Red Team](https://github.com/redcanaryco/atomic-red-team) `atomics/` directory |
| Schema | `mitre_id`, `technique_name`, `command` |
| Coverage | All `T*.yaml` files in the atomics tree |

**Scraping process:**
1. Walks the `atomic-red-team/atomics/` directory recursively.
2. For every YAML file matching `T\d{4}.*\.yaml`, loads it with `yaml.safe_load`.
3. Iterates `atomic_tests`; extracts `executor.command` (falls back to `executor.powershell_command`).
4. Collapses whitespace, lowercases, and saves each command with its MITRE ID and test name.

### MITRE Vector Atlas — `mitre_atlas.index` + `mitre_atlas_metadata.csv`

Built by `vector_atlas_builder.py`. Used at inference time for zero-day attribution.

- Embeds every command in `mitre_atlas_raw.csv` with `roberta-base` (CLS token, 768-D).
- Stores vectors in a FAISS `IndexFlatL2` index.
- Saves a companion `mitre_atlas_metadata.csv` mapping each index position to `(mitre_id, technique_name, command)`.

## 2. Test Methodology

Script: `eval.py` — **`NormalizedEvaluator.run_war_room()`**

1. Loads `anomaly_engine.pt` — reads `model_state` and `threshold` from the checkpoint.
2. Samples **1,000** commands from `synthetic_benign_baseline.csv` and loads all rows from `mitre_atlas_raw.csv`.
3. For every command, applies `normalize_command()` then tokenises with `microsoft/codebert-base` at `max_length=96`.
4. Runs a forward pass to get the CLS embedding (`emb`) and the decoder reconstruction (`rec`).
5. Computes per-sample reconstruction error: `mean((emb - rec)²)`.
6. Reports:
   - **Max Benign Noise** — worst-case reconstruction error on a benign sample
   - **Min Malicious Signal** — best-case reconstruction error on a malicious sample
   - **Safety Gap** — `min_malicious / max_benign` (a gap > 1.0 means the distributions are fully separated)
   - **Detection Rate** — % of malicious commands with error above threshold
   - **False Positive Rate** — % of benign commands with error above threshold

## 3. Stress Test Methodology

### 3a. War Room competitive test — `stress.py` (`WarRoomEvaluator.run_competitive_test()`)

A harder version of the eval sweep:

1. Samples up to **2,000** benign commands (covers more of the normal distribution than the 1,000-sample eval).
2. Loads all malicious commands from `mitre_atlas_raw.csv`.
3. Applies the full `normalize_command()` pipeline to every command before scoring — this simulates fuzzed or obfuscated production input hitting the sanitizer.
4. Computes the same gap analysis as `eval.py` but also prints a verdict:
   - **MATHEMATICALLY SEPARATED** if `min_malicious > max_benign` (gap ≥ 1.0×)
   - **OVERLAPPING MANIFOLD** if distributions overlap, with the % of benign commands noisier than the cleanest attack.

### 3b. Per-technique audit — `audit.py` (`AnomalyAuditor.audit_mitre_techniques()`)

Deep-dives into detection coverage per MITRE ID:

1. Groups `mitre_atlas_raw.csv` by `mitre_id`.
2. For each technique, computes reconstruction error on every individual command.
3. Records:
   - Average error across all commands in the technique
   - Minimum error (the hardest-to-detect command — the "worst offender")
   - Detection status: `DETECTED` if `min_error > threshold`, else `BYPASSED`
4. Prints a ranked table of the top 20 most-evasive techniques (sorted by `min_error` ascending).
5. Can be invoked via CLI with `--model` and `--csv` flags.

## 4. Training Methodology

Script: `train_autoencoder.py` — **`train_hardened_engine()`**

### Overview

Phase 2 trains a **contrastive autoencoder** (not a classifier). The model learns to reconstruct benign command embeddings faithfully while being forced to produce high reconstruction error on malicious ones. An anomaly threshold derived from the benign training distribution is then stored with the model for use at inference time.

### Pipeline

1. **Normalisation** — every command is passed through `normalize_command()` before the tokeniser ever sees it:
   - Lowercase
   - Strip `^` (CMD caret) and `` ` `` (PowerShell backtick)
   - Convert `/` → `\`
   - Collapse multiple whitespace
   - Strip `> nul 2>&1` and `>nul` redirections
   - Normalise `\.\` path artifacts

2. **Dataset** — `ContrastiveNormalizedDataset`:
   - Holds a list of normalised benign and malicious commands.
   - `__getitem__` returns one benign sample and one malicious sample (malicious index wraps with `%`).

3. **Model** — `SecurityAgentX_Model` (CodeBERT-based):
   - **Encoder**: `microsoft/codebert-base` — a RoBERTa-family model pre-trained on code.
   - **Decoder head**: `Linear(768→1024) → LayerNorm → GELU → Linear(1024→1024) → LayerNorm → GELU → Linear(1024→768)` — a deep reconstruction head intentionally larger than the encoder bottleneck, making reconstruction non-trivial.

4. **Loss** — contrastive MSE:
   - `loss_benign = MSE(reconstructed_benign, embedding_benign)` — drive reconstruction error to zero for benign.
   - `loss_malicious = mean(clamp(margin - MSE(reconstructed_malicious, embedding_malicious), min=0))` — push malicious reconstruction error above `margin`.
   - `total_loss = loss_benign + 3.0 × loss_malicious` — malicious penalty is weighted 3× to ensure clear separation.

5. **Threshold derivation** — after training, the model is put in eval mode and reconstruction errors are computed over the entire benign training set. The threshold is set to: `mean(errors) + 4 × std(errors)`.

6. **Checkpoint** — saved to `anomaly_engine.pt` as `{"model_state": ..., "threshold": ...}`.

## 5. Hyperparameters

| Parameter | Value | Notes |
|---|---|---|
| Base encoder | `microsoft/codebert-base` | RoBERTa pre-trained on code; 768-D hidden |
| `max_length` (tokenizer) | 96 tokens | Shorter than phase 1 (128); sufficient for shell commands |
| `batch_size` | 64 | |
| `epochs` | 3 | |
| `optimizer` | AdamW | |
| `learning_rate` | `4e-5` | |
| Contrastive `margin` | 0.008 | Minimum required MSE gap between benign and malicious |
| Malicious loss weight | 3.0 | Multiplier applied to `loss_malicious` in total loss |
| Mixed precision | bf16 (or fp16 fallback) | Via `torch.amp.autocast` + `GradScaler` |
| Threshold formula | `μ + 4σ` of benign training errors | Set at the end of training from the full benign pass |

## 6. How the Inference Engine Works (Step-by-Step)

The inference logic lives in `inference_engine.py` — `HybridSecurityEngine.analyze_command()`.

### Startup

1. Loads `anomaly_engine.pt` and instantiates `SecurityAgentX_Model(num_labels=3)` (the unified architecture that adds a classifier head and a SiLU-based decoder on top of `roberta-base`).
2. Reads `threshold` from the checkpoint (falls back to `0.001` if absent).
3. Loads the FAISS vector atlas (`mitre_atlas.index`) and the companion `mitre_atlas_metadata.csv`.
4. Sets `self.labels = ["T1003.002", "T1562", "T1134"]` — the three known MITRE TTPs for direct classification.
5. Model is set to `eval()` mode; uses bf16 (or fp16) mixed precision on CUDA.

### Per-command inference — 3-stage decision tree

**Stage 1 — Anomaly check (heuristic gate)**

1. Lowercases the raw command (lightweight normalisation at the engine level).
2. Tokenises with `roberta-base` at `max_length=128`.
3. Runs a single forward pass: obtains CLS embedding (`emb`), decoder reconstruction (`rec`), and classifier logits.
4. Computes reconstruction error: `mean((emb - rec)²)`.
5. If `error ≤ threshold` → **BENIGN** verdict, returns immediately.

```json
{
  "verdict": "BENIGN",
  "detection_type": "HEURISTIC_MATCH",
  "reconstruction_error": "0.00000312",
  "command": "<original>"
}
```

**Stage 2 — Known TTP classification (if anomalous)**

6. Applies softmax to the classifier logits; reads the top class and its confidence.
7. If `confidence ≥ 0.70` → the command maps to one of the 3 known TTPs.

```json
{
  "verdict": "MALICIOUS",
  "detection_type": "KNOWN_TTP_MATCH",
  "mitre_id": "T1003.002",
  "confidence": "98.47%",
  "command": "<original>"
}
```

**Stage 3 — Zero-day attribution via FAISS (if classifier is uncertain)**

8. If `confidence < 0.70` the classifier is unsure — the command may be a technique outside the 3 trained classes.
9. The CLS embedding is cast to `float32` and searched against the FAISS atlas with `k=1` (nearest neighbour, L2 distance).
10. The closest match's `mitre_id` and `technique_name` are read from `mitre_atlas_metadata.csv`.
11. Similarity is reported as `1 - L2_distance`.

```json
{
  "verdict": "MALICIOUS",
  "detection_type": "ZERO_DAY_ANOMALY",
  "mitre_id": "T1059.001",
  "technique_name": "PowerShell Empire Launcher",
  "similarity": "0.8732",
  "command": "<original>"
}
```

### Decision flow summary

```
Input command
    │
    ▼
normalize → tokenise → forward pass
    │
    ├── error ≤ threshold ──────────────► BENIGN (HEURISTIC_MATCH)
    │
    └── error > threshold
            │
            ├── classifier confidence ≥ 0.70 ──► MALICIOUS (KNOWN_TTP_MATCH)
            │
            └── classifier confidence < 0.70 ──► FAISS k=1 search
                                                        │
                                                        └──► MALICIOUS (ZERO_DAY_ANOMALY)
```
